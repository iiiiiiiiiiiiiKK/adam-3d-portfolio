## 3. Core features in depth

### 1. Skills & Tools — an extensible capability hub

DeerFlow treats skills as first-class citizens. A skill is a version-managed Markdown/YAML resource that loads dynamically like a plugin; a tool is the code function that actually executes commands behind a skill. With the two decoupled, an ops person can add capability without writing code.

It has native Claude Code integration: just say the following to a coding agent such as Claude Code, Codex, Cursor or Windsurf — `Help me clone DeerFlow if needed, then bootstrap it for local development by following https://raw.githubusercontent.com/bytedance/deer-flow/main/Install.md` — and the agent clones the repo and gets it running locally for you.

### 2. Sub-Agents — an execution network that splits work in parallel

Complex tasks can be decomposed across multiple concurrent sub-agents — "one handles retrieval, one writes code, one draws diagrams." Each sub-agent gets its own context window and tool set, and results are aggregated back into the main agent. The design idea is similar to Claude Multi-Agent and AutoGen, but DeerFlow exposes finer runtime control through parameters such as `subagents.max_total_per_run`, preventing infinite recursion or resource exhaustion.

### 3. Sandbox & File System — a safe execution environment

DeerFlow supports three sandbox modes: **local direct execution, Docker container isolation, and K8s Pod isolation**. All code execution is confined to a sandbox, and file reads and writes go through restricted paths, avoiding the "AI formatted my hard drive" disaster. Docker mode is recommended in production; local direct execution is faster in development; when several users share an instance, Redis-backed sandbox ownership management stops "the colleague next door's code from deleting the container I'm using."

### 4. Long-Term Memory & Session Goals — an assistant that doesn't forget

Traditional chatbots forget the moment the conversation ends. DeerFlow makes memory a persistent module: user preferences, project background and past experience are all callable across sessions. Nicer still are "session goals" — you can tell it "help me do competitor analysis over the next 30 minutes," and it keeps tracking completion and reminds you when time is up. Paired with manual context compaction, old turns in a long task can be explicitly archived, freeing window space for new content.

### 5. Context Engineering & IM Channels — end-to-end engineering

DeerFlow treats context engineering as a module in its own right: what enters the context, how it's ordered, when it's compacted, and how it's traced back all follow explicit policies. IM Channels let it receive tasks directly on Telegram, Slack, Feishu, WeCom and DingTalk with no public IP — set `bot_token` and your AI assistant lives in the team chat.

- **TUI terminal workbench**: beyond the Web UI, a built-in Terminal Workbench lets developers talk to DeerFlow straight from an SSH session.

## 5. Use cases and who it's for

**Case 1: long-chain research reports.** Type "write me a 2025 China new-energy vehicle market report" and DeerFlow decomposes the sub-tasks itself (find data sources, scrape data, run analysis, draw charts, write the summary) and outputs PDF/PPTX.

**Case 2: automated code workflows.** Have DeerFlow watch GitHub issues continuously, then reproduce, fix and open a PR automatically — combined with Claude Code integration, that's an "AI programmer on duty" pattern.

**Case 3: team IM assistant.** Wire DeerFlow into Feishu/WeCom/Slack and it looks things up, books meeting rooms and writes weekly reports in the group, with no extra public webhook development.

**Who it suits**: teams that need to move "AI writes docs / does research / runs code" from one-off demos to everyday productivity; mid-level and backend engineers who want a private agent platform without building the wheels from scratch; enterprises with data compliance requirements that need local deployment.

**Who it doesn't suit**: lightweight users who just want a few chat turns; absolute beginners who can't tolerate a command line (the minimum bar is running `make`).

## 7. Getting started fast

**Prerequisites**: Python 3.12+, Node.js 22+, pnpm, uv, Docker (optional).

**One-line start (recommended for Claude Code/Codex users)**: paste this into your coding agent
```
Help me clone DeerFlow if needed, then bootstrap it for local development by following https://raw.githubusercontent.com/bytedance/deer-flow/main/Install.md
```
The agent clones the repo, picks Docker and gives you the next command.

**Manual start**:
```bash
git clone https://github.com/bytedance/deer-flow.git
cd deer-flow
make setup       # interactive wizard, generates config.yaml and .env in about 2 minutes
make doctor      # self-check
make docker-start  # one-command startup in Docker mode
```
Then visit http://localhost:2026 for the Web UI. If something breaks, run `make support-bundle` to generate a diagnostic bundle you can paste straight into a GitHub issue.

**Advanced tips**: for production, use `make up` to build production images; in multi-worker setups be sure to configure Postgres + Redis Stream Bridge + `run_ownership.heartbeat_enabled: true`; on mainland China networks, set `UV_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple` and `NPM_REGISTRY=https://registry.npmmirror.com` to speed things up.
