## 1. Intro: why you need this tool

When you're doing reverse engineering, an AI assistant facing an APK sample often gets stuck at the first choice: decompile with jadx, or go straight to Frida dynamic hooking? When the encryption parameters in front-end JS won't crack, do you hang BurpSuite and capture traffic, or analyze the obfuscated opcode VM? Worse, on the same machine IDA, Ghidra, radare2, apktool and yara are scattered all over the place, so every task means digging through docs again, guessing commands, and stepping on the same trap.

An internal 2025 survey by a Chinese security team found that security researchers waste 40% of their working time on "picking tools + tuning the environment + trying commands", leaving less than 30% for actual vulnerability analysis and report writing. AI is good at writing code, but what it lacks is a set of "skill routing" for reverse engineering, pentesting and security research scenarios — hand it an APK and it doesn't know what step one is; hand it a chunk of obfuscated JS and it generates a pile of pseudo-code that won't execute.

`reverse-skill` exists to fix exactly this: after an AI agent receives a task, it routes itself to the right methodology, checks the local toolchain, executes a reproducible workflow, and turns what it learned into a reusable knowledge base.

Four keywords capture the core features: **Routing**, **Bootstrap**, **Evolution** and **Ops**. It isn't a tool — it's a methodology scheduling layer on top of your tools.

## 3. Core features in depth

### 1. AI routing: the end of guessing commands

Conventional AI assistants handling a security task tend to just print `jadx-cli` commands without checking whether a JDK is even installed. `reverse-skill`'s `master-route.ps1` script acts as first-level triage: after receiving the task it reads `RULES.md` for global rules, loads `case-init` to generate a scope (authorization + network profile), and finally dispatches the task to the matching scenario skill (apk-reverse, js-reverse, pwn-chain and so on).

The routing matrix in `skills/routing.md` maps task types to precise methodologies: APK → jadx/apktool; ELF binaries → IDA/radare2; front-end JS encryption → Reqable MCP + js-reverse; CTF → CTF-Sandbox-Orchestrator (with 40+ sub-skills built in). This matrix isn't static documentation — it filters out tools that aren't installed locally based on `tool-index.md`, so the AI stops handing you "air commands".

### 2. On-demand toolchain bootstrap: fill in whatever is missing

The repo ships `refresh-tool-index.ps1` (Windows) and `refresh-tool-index.sh` (Linux/macOS). Running them scans the machine for installed tools such as jadx, frida, nmap, ghidra and burpsuite-mcp, and generates the `skills/tool-index.md` index. Before dispatching a task, the AI checks that table and, when something is missing, either tells the user where to install it or switches to an alternative.

Platform differentiation is another highlight: Kali Linux users run `kali/scripts/refresh-tool-index.sh`, which recognizes Kali's preinstalled security toolset automatically; Ubuntu/Debian and macOS each have their own deployment docs, `docs/platforms/linux.md` and `docs/platforms/macos.md`. This bootstrap mechanism means the AI no longer depends on a hardcoded tool list.

### 3. A self-evolving experience base: field-journal and the Evidence chain

After every task, contract files under `skills/ops/` force three kinds of records: Evidence (raw evidence, such as a dumped dex or a post-hook memory snapshot), Finding (the vulnerability or logic discovery) and Path (the reproduction path). These records go into `field-journal/`, and the next time a similar task fires, the AI searches past experience first and reuses the methodology instead of stepping on the same trap again.

Take OLLVM deobfuscation: the repo ships `skills/reverse-engineering/references/ollvm-deobfuscation.md`, paired with `skills/reverse-engineering/dsl-vm-reverse/` for custom opcode VMs. When the AI handles an obfuscated sample, it first checks the journal for similar cases, then decides between an llvm-pass and unicorn emulation.

### 4. Ops contract auditing: the scope gate holds the compliance line

Authorization auditing is the first gate of security research. `RULES.md` mandates that before any "ACT-class" operation, the AI must complete `case-init` and generate scope.md (explicit authorization scope + network profile). Active scanning of unauthorized targets is forbidden; dynamic execution of unauthorized samples is forbidden. This "scope gate before ACT" mechanism writes compliance constraints into the routing layer instead of relying on users' good intentions.

## 7. Getting started fast

**Environment setup:**

- JDK (a dependency of jadx/apktool)
- Node.js 22.12+ (JS toolchain and MCP services)
- Python 3.x (Frida and helper scripts)
- A coding AI client: Claude Code / Cursor / Cline, your pick

**Three-step deployment:**

1. Clone the repo:
   `git clone https://github.com/zhaoxuya520/reverse-skill.git`

2. Refresh the tool index (pick the command for your platform):
   - Windows: `powershell -File skills/scripts/refresh-tool-index.ps1`
   - Linux/macOS: `bash skills/scripts/refresh-tool-index.sh`
   - Kali: `bash kali/scripts/refresh-tool-index.sh`

3. Load it into your AI client: feed `README_AI.md` to Claude Code or Cursor and let the AI initialize the workspace following the bootstrap instructions.

**Minimal working example:**

With an APK sample in hand, type this in your AI client: "Analyze samples/test.apk following the reverse-skill flow". The AI routes itself to `skills/apk-reverse/`, runs `case-init` to generate scope.md, calls jadx to decompile, and outputs a timeline plus evidence records.

**Advanced tips:**

- Read `skills/MASTER-ROUTING.md` first (the PRIMARY fast path) to understand routing priority
- Use `skills/scripts/master-route.ps1` for a one-off triage test
- For long-term use, add the `work/` directory to gitignore and keep case data local
